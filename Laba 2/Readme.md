## Цель работы

Реализовать игру для двух участников, в которой человек играет против компьютера. Компьютер должен выбирать ход с помощью Minimax: рассматривать возможные продолжения, учитывать ответ человека и выбирать лучший результат при самой неудобной для себя игре соперника.

## Описание игры

Для работы выбран вариант 1 - "Крестики-нолики" на поле 3x3. Игроки по очереди ставят X или O в свободные клетки. Для победы нужно собрать три своих символа в строке, столбце или по диагонали. Если поле заполнено и никто не победил, партия заканчивается ничьей.

Игра выполнена в Unity в виде 2D-интерфейса. Можно выбрать, кто начинает партию. Первый игрок получает X, второй - O. Во время ответа компьютера клетки недоступны для нажатия. После завершения партии отображается результат и обновляется счет. При перезапуске поле очищается, а счет сохраняется до выхода из игры.

В отдельной панели показан последний расчет ИИ: оценки доступных клеток перед его ходом, выбранный вариант, количество просмотренных позиций, глубина и время поиска.

## Структура кода

В папке `Code` находятся четыре файла:

| Файл | Назначение |
| --- | --- |
| `GameState.cs` | Хранение поля, получение ходов, применение хода и проверка результата |
| `MinimaxAI.cs` | Оценочная функция, рекурсивный Minimax и выбор хода ИИ |
| `GameController.cs` | Очередность ходов человека и ИИ, новая партия, счет и обновление интерфейса |
| `BoardCell.cs` | Обработка нажатия на клетку и отображение ее символа и цвета |

## Представление игрового состояния

Поле хранится в массиве из девяти элементов. Каждая клетка имеет одно из трех значений: `Empty`, `Cross` или `Nought`. Кроме поля, состояние содержит текущего игрока и количество сделанных ходов.

| Элемент | Что делает |
| --- | --- |
| `GetLegalMoves()` | Возвращает индексы свободных клеток. После окончания партии возвращает пустой список |
| `ApplyMove(index)` | Создает копию состояния, ставит символ в выбранную клетку и передает ход другому игроку |
| `Winner` | Проверяет восемь возможных выигрышных линий и возвращает победителя |
| `IsTerminal` | Определяет, закончилась ли партия победой или заполнением поля |
| `IsDraw` | Определяет ничью: поле заполнено, но победителя нет |

При переборе каждый ход применяется к копии состояния. Благодаря этому проверка одного продолжения не изменяет исходное поле и не мешает проверке других вариантов. Ход в занятую клетку, за пределы поля или после окончания партии не допускается.

## Работа Minimax

Метод `FindBestMove` по очереди пробует допустимые ходы ИИ. Для каждого варианта он получает следующее состояние и вызывает `Minimax(state, depth, isMaximizing)`.

Рекурсия работает следующим образом:

1. Сначала проверяется, закончилась ли партия. Если да, возвращается оценка результата.
2. Если сейчас ход ИИ, из оценок продолжений выбирается максимальная.
3. Если сейчас ход человека, выбирается минимальная оценка. Предполагается, что человек ответит наиболее выгодным для себя способом.
4. При переходе к следующему ходу сторона меняется, а глубина увеличивается на один.
5. Оценки возвращаются к исходной позиции. ИИ выбирает ход с наибольшей итоговой оценкой.

Дерево строится через последовательное создание новых состояний. Полностью хранить его в памяти не нужно: после проверки одной ветки программа переходит к следующей.

Если несколько ходов получили одинаковую оценку, используется постоянный порядок: центр, углы, края. Среди равных вариантов немедленная победа имеет приоритет. Сама оценка результата от этого не меняется.

## Оценочная функция

Метод `Evaluate` оценивает результат с точки зрения компьютера:

| Результат | Оценка |
| --- | ---: |
| Победа ИИ | +10 |
| Победа человека | -10 |
| Ничья | 0 |

Для незаконченного состояния метод тоже возвращает 0, но Minimax не останавливается на таком состоянии. Он продолжает поиск до победы, поражения или ничьей. Дополнительные эвристики и штрафы за глубину не используются.

## Пример выбора хода

Человек играет за X, компьютер - за O. Клетки нумеруются слева направо, сверху вниз, от 1 до 9. После двух ходов человека и ответа ИИ в центр поле выглядит так:

```text
 X | X | .
---+---+---
 . | O | .
---+---+---
 . | . | .
```

Сейчас ход компьютера. Если он поставит O в клетку 3, верхняя строка будет закрыта, и при дальнейшей правильной игре можно получить ничью. Оценка такого хода равна 0.

Любой другой ход получает оценку -10: человек следующим ходом поставит X в клетку 3 и выиграет. Minimax учитывает этот ответ и выбирает клетку 3, поскольку 0 больше -10. В коде ей соответствует индекс 2.

## Глубина поиска

В этой игре используется полный перебор. Искусственного ограничения глубины нет, потому что поле небольшое и за всю партию можно сделать не больше девяти ходов. Если победа наступает раньше, соответствующая ветка заканчивается сразу.

Параметр `depth` показывает, сколько ходов пройдено от исходной позиции. Он используется для статистики поиска. По мере заполнения поля возможных продолжений становится меньше, поэтому отдельная эвристическая оценка промежуточных позиций не требуется.

## Проверка работы

Проверены определение победы и ничьей, запрет недопустимых ходов, смена игрока и сохранение исходного состояния при переборе. Отдельно проверены ситуации, в которых ИИ может сразу победить или должен закрыть выигрышный ход человека.

Для проверки стратегии перебраны все возможные продолжения человека против выбранных ИИ ходов. Проверка проведена для обеих сторон: когда компьютер начинает первым и когда он ходит вторым. При игре двух оптимальных игроков партия заканчивается ничьей.

Также проверены перезапуск во время ответа ИИ, смена первого игрока и запрет повторного хода человека, пока компьютер выбирает ответ.

## Вывод

В работе реализован искусственный игрок, который выбирает ход с помощью Minimax. Он учитывает возможные ответы соперника, на своих уровнях выбирает максимум, а на уровнях человека - минимум. Полный перебор до конца партии позволяет выбирать оптимальные ходы и не проигрывать человеку.
